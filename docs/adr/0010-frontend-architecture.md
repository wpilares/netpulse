# ADR 0010: Frontend architecture: axios client, TanStack Query cache and a token-based design system

- Status: Accepted
- Date: 2026-10-27

## Context

The v1.0 dashboard worked but was engineered rather than designed. Every feature owned a hand-written hook that called bare `fetch`, parsed the body with ad hoc type guards and reimplemented polling, loading and error handling on its own; a `fetcher` prop was drilled from `App` into each panel so tests could stub it. All styling lived in one global `styles.css` with BEM class names, pills and badges were duplicated across three components, and the dark theme followed the operating system with no way to pick one. Alerts arriving over the WebSocket and the REST list of open alerts were kept in separate state, which let an in-flight REST response overwrite a newer frame.

v1.1 set three goals without changing the API contract: a modern, responsive dashboard with proper loading, empty and error states; a theme selector with light, dark and system modes that persists and never flashes on reload; and a set of reusable components so that new panels compose existing parts instead of restyling them.

## Decision

**HTTP goes through an `ApiClient` port implemented with axios.** `src/api/client.ts` declares the `ApiClient` interface (`getHealth`, `getKpiSummary`, `getTopology`, `listAlerts`, `acknowledgeAlert`) and `createApiClient` builds it on an axios instance with `adapter: "fetch"`. The adapter takes an optional `fetchImpl` through `env.fetch`, so tests inject a `Response`-based fake per instance instead of stubbing a global. A response interceptor normalises every failure into a typed `ApiError` whose `kind` is `network`, `not_found`, `unavailable` or `invalid`; callers narrow on the kind and never see axios types. `GET /health` keeps reading a 503 body, because the API reports a degraded database that way, so that request alone accepts 200 and 503 through `validateStatus`. The instance is handed to the tree by `ApiClientProvider` (`src/api/ApiClientProvider.tsx`) and read with `useApiClient`; no component imports axios.

**Every payload is validated at the boundary with zod.** `src/api/schemas.ts` defines one schema per REST response and a discriminated union for the WebSocket frames (`hello`, `pong`, `error`, `heartbeat`, `store_unavailable`, `kpis`, `alerts`). The client decodes each response with its schema and raises `ApiError("invalid")` on a mismatch; the socket hook drops frames that do not parse. The TypeScript types (`ApiHealthReport`, `KpiSnapshot`, `Topology`, `Alert`, `AlertList`, `LiveFrame` and the rest) are `z.infer` of the schemas and keep the names the v1.0 hand-written types had, so feature code did not change its imports.

**TanStack Query is the server cache.** `src/api/queryClient.ts` creates the `QueryClient` (one retry, no refetch on window focus) and `src/api/keys.ts` holds every query and mutation key, so the cache has one vocabulary. Features expose small hooks over `useQuery`: health polls every 10 s, topology every 30 s, the KPI summary and the open alerts load once and are then fed by the socket, and the resolved alerts load on demand. Acknowledging an alert is a `useMutation` in `src/features/alerts/useAcknowledgeAlert.ts` that writes `acknowledged_at` into the cached list optimistically, rolls it back on error and upserts the returned alert on success; pending ids come from `useMutationState`, so the row knows it is in flight without local state.

**WebSocket frames are pushed into the cache synchronously.** `src/features/telemetry/useTelemetrySocket.ts` owns the connection, backoff and ping, and hands every parsed frame to `applyLiveFrame` in `src/features/telemetry/cacheBridge.ts`. A `kpis` frame cancels the in-flight summary query and replaces its data; an `alerts` frame cancels the open-alerts query and merges the frame into the cached list (replacing it when it is the first snapshot after a connect). Both happen in the socket callback, before React schedules a render, so a frame always wins over a REST response that is still in flight. The REST query for open alerts is disabled once the first snapshot has arrived, and re-enabled by a reconnect until the next snapshot. Panels therefore read a single source of truth and the race that made the v1.0 alerts test flaky is closed by construction.

**Design tokens drive both themes.** `src/styles/tokens.css` declares the type scale, spacing, radii, motion and every colour as custom properties on `:root`; the dark palette is scoped to `:root[data-theme="dark"]` and, inside the `prefers-color-scheme: dark` media query, to `:root:not([data-theme="light"])`, each block setting its own `color-scheme`. `src/theme/theme.ts` holds the pure functions (`readStoredTheme`, `writeStoredTheme`, `resolveTheme`, `applyThemeAttribute`) and `src/theme/ThemeProvider.tsx` the React state: the preference is `light`, `dark` or `system`, persisted in `localStorage` under `netpulse.theme`, with `system` stored as the absence of the key and resolved with `matchMedia`. An inline script in `index.html` reads the key and sets `data-theme` on `<html>` before the bundle loads, so the first paint already has the right palette. `ThemeToggle` in `src/components/ui` is a segmented control over the three modes.

**CSS Modules, lucide-react, no framework.** Each component owns a `*.module.css` file next to it; Biome lints them with `css.parser.cssModules` enabled in `biome.json`. Icons come from `lucide-react` through one `Icon` atom. `src/styles/global.css` holds the reset, the body background, the `:focus-visible` ring, the `data-tone` colour mapping, `.sr-only` and the reduced-motion override; everything else lives in a module. There is no Tailwind and no component library.

**Atomic components and a container/presentational split.** `src/components/ui` holds the atoms (`Button`, `Badge`, `Card`, `Pill`, `SegmentedControl`, `Switch`, `Skeleton`, `Icon`, `VisuallyHidden`) and the molecules (`StatTile`, `StatusPill`, `EmptyState`, `ErrorState`, `ChartFrame`, `ThemeToggle`), exported from one `index.ts`. Each feature splits into containers that own queries and socket state (`SummaryPanel`, `AlertsPanel`, `TopologyPanel`, `SwitchPortsPanel`) and views that render props only (`SummaryGrid`, `AlertsPanelView`, `AlertRow`, `TopologyView`, `PortCard`, `PortChart`). `src/app/AppShell.tsx` lays the header, the responsive grid and the footer out around them. Views are tested with plain `render`; containers and hooks are tested through `renderWithProviders` and `renderHookWithProviders` in `src/test/renderWithProviders.tsx`, which mount a fresh `QueryClient` with retries off, the `ThemeProvider` and an `ApiClientProvider` around the fake client from `src/test/fakeApiClient.ts`.

### Alternatives considered

- **Keep bare `fetch` behind the existing hooks.** It has no interceptors, so every hook kept its own error mapping and the `fetcher` injection stayed as a prop. axios with the fetch adapter costs one dependency and gives one interceptor, request cancellation through `AbortSignal` and a port that tests fake per instance.
- **Tailwind or shadcn/ui.** Both bring a build-time pipeline and a visual language that would fight the token set; shadcn also copies component sources into the repository to maintain. CSS Modules keep every style local to its component with no extra tooling, and the tokens are plain custom properties any file can read.
- **Zustand or Redux for server state.** They store the data but leave polling, deduplication, cancellation, cache invalidation and optimistic updates to hand-written code, which is exactly what v1.0 had. TanStack Query owns those concerns, and the socket bridge only needs `setQueryData` and `cancelQueries` to feed it.

## Consequences

- Four runtime dependencies were added (`axios`, `zod`, `@tanstack/react-query`, `lucide-react`) and one dev dependency (`@tanstack/react-query-devtools`, mounted only in development builds). The production bundle grows accordingly.
- Every REST response and every WebSocket frame is parsed by zod. A `kpis` frame on the demo fleet is a few kilobytes every 5 s, so the cost is not measurable, but a much larger fleet would pay it per frame; validating only the discriminator for `kpis` frames is the first thing to relax if that happens.
- A payload that drifts from the schema now fails loudly as `ApiError("invalid")` or a dropped frame instead of rendering `undefined`. That is the intended behaviour and it makes schema changes on the API a frontend change too.
- Styles are local by construction, so a class name only collides inside its own module; the price is a naming discipline (one module per component, tokens rather than literal values) that Biome cannot enforce.
- Tests that touch a hook or a container must mount the providers; a bare `render` of a container throws from `useApiClient`. `renderWithProviders` keeps that to one line, and the fake client is the only place a test describes the API.
- The cache bridge mutates the query cache from outside React, so it must stay synchronous and must cancel the matching query before writing, or the race it fixes returns. Its tests assert that the write is synchronous and that a frame wins over a REST list resolving after it.
- Theme and layout are now verified in both modes: the v1.1 pass with Playwright and axe found no serious or critical accessibility violations in light or dark, at desktop and at 390 px.
